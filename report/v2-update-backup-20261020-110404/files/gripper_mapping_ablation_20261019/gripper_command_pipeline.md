# 夹爪从原始 Action Chunk 到 SDK 指令的完整处理链路

分析日期：2026-10-19。

本报告对应 `/home/bjtc/Sophix/g1-open-rail` 中的 LingBot 部署链路，以及 `conf/lingbot_ori_package.yaml` 配置。报告保存在当前工作目录 `ORI-lingbot-vlaV2` 下，但不表示已经检查或修改了 V2 的部署实现。以下主要解释右夹爪；左夹爪的特殊处理见第 11 步。

本文所说的“原始 action chunk”，是模型部署接口返回的动作序列，已经经过模型内部输出后处理，不是网络内部的归一化张量。本报告未修改部署代码或机器人状态。

## 1. 总体流程

```text
模型接口返回 action chunk
    ↓
提取右夹爪维度，建立动作时间轴
    ↓
当前 chunk 内做 9 点均值滤波
    ↓
接近 0 / 1 的均值吸附到端点
    ↓
在 3.75 ms 时间网格上，取相邻原始点的平均值
    ↓
根据观测到处理时刻的延迟选择新 chunk 起始索引
    ↓
块间处理：夹爪直接使用新 chunk，不做手臂的 min_jerk 过渡
    ↓
夹爪目标提前取 5 个拟合采样点
    ↓
控制循环推进索引，每 9 次执行调用发送一次夹爪目标
    ↓
将右夹爪目标裁剪到 [0,1]
    ↓
四次方映射
    ↓
SDK 发布位置命令
```

需要区分三种作用：

| 类型 | 操作 | 主要影响 |
|---|---|---|
| 改变数值 | 均值滤波、端点吸附、相邻平均、裁剪、四次方映射 | 当前目标的大小 |
| 改变取样位置或时机 | 延迟补偿、采样偏移、索引推进、每 9 次调用发送一次 | 选中哪个目标、何时发送 |
| 改变轨迹来源 | 新 chunk 替换旧 chunk | 前后目标是否一致 |

## 2. 第一步：原始动作的维度与含义

当前分析配置中，一个 chunk 通常有 50 个未来动作，每个动作 16 维：

```python
actions.shape == (50, 16)
actions[:, 14]  # 左夹爪
actions[:, 15]  # 右夹爪，下标从 0 开始
```

右夹爪采用绝对位置目标：

- `0`：全开目标。
- `1`：全闭目标。
- 中间值：中间位置目标，不是“闭合概率”，也不能直接解释为夹持力百分比。

夹爪动作不会像部分手臂动作那样加上当前观测状态。服务端适配器检查动作形状及有限值，然后返回动作序列，不在这一层把夹爪二值化。

源码：`g1-open-rail/server/models/lingbot_vla/lingbot_vla.py`，`infer()`，约第 87 行；夹爪绝对目标配置见 `ORI-lingbot-vla/configs/robot_configs/package_a2d.yaml` 中的 `action.effector.position`，`subtract_state: false`。

## 3. 第二步：建立原始动作时间轴

当前配置：

```yaml
controller:
  raw_fps: 30
  speed: 1.0
  period: 3.75
```

在 speed 为 1 时，原始动作间隔约为 33.33 ms：

```text
第 0 点：   0 ms
第 1 点：  33.33 ms
第 2 点：  66.67 ms
……
第 49 点：1633.33 ms
```

这里必须区分原始动作网格（30 Hz）和后续拟合控制网格（每点 3.75 ms）。建立时间轴和客户端按“维度 × 时间”存储动作，都不会改变夹爪数值。

## 4. 第三步：当前 chunk 内的 9 点均值滤波

配置中的 `filter_window_size: 4` 表示窗口半径，实际窗口长度为：

```text
前 4 点 + 当前点 + 后 4 点 = 9 点
```

对于窗口完整的内部位置：

```text
m[i] = (g[i-4] + ... + g[i] + ... + g[i+4]) / 9
```

例如，窗口内是 `1 1 1 1 0 1 1 1 1`，均值为 `8/9 ≈ 0.8889`。单个低值会被周围的高值平均。

边缘处不补零、不缩短窗口，而是将整个窗口移到有效范围内；最前面的几个位置会使用前 9 个原始值。若整个 chunk 短于 9 点，窗口长度限制为实际长度。

当前实现使用原始输入求各窗口均值，不把前面已经滤波或吸附的结果递归用于后面的窗口。

两个重要限制：

1. 只使用当前 chunk 内的数据，不与旧 chunk 尾部共同滤波，因此不保证跨块一致性。
2. 使用未来预测点。在计划释放附近，未来的打开目标可能提前拉低当前均值。

源码：`client/core/intra_chunk_smoother.py`，`_gripper_traj_fitting_batch()`，约第 242 行。

## 5. 第四步：端点吸附

均值算完后应用：

```python
if mean > 0.95:
    value = 1.0
elif mean < 0.05:
    value = 0.0
else:
    value = mean
```

这里是严格大于或小于；等于阈值时保留均值，实际浮点计算也可能影响极接近阈值的比较。

| 均值 | 吸附后 |
|---:|---:|
| 0.03 | 0 |
| 0.20 | 0.20 |
| 0.60 | 0.60 |
| 0.97 | 1 |

这不是以 0.5 为界的二值化，中间区域仍保留连续数值。

## 6. 第五步：相邻平均，生成 3.75 ms 网格上的目标

代码生成拟合时间网格：

```python
timestamps_fitted = np.arange(start_time, end_time, time_step)
```

当前 `time_step` 对应 0.00375 秒。对每个拟合时刻，寻找相邻原始时间点，并取经过滤波和吸附后的两点平均：

```text
f(t) = (s[left] + s[right]) / 2
```

例如，33.33 ms 时目标为 0.8，66.67 ms 时目标为 0.6，它们之间的拟合点通常都取 0.7。

这不是按时间距离加权的标准线性插值。靠近左点或右点，代码都采用相同的两点平均，因此生成的是分段保持的平均目标，而非连续斜坡。搜索使用 `side='left'`：恰好落在非首个原始时间点时，也会用该点和前一点平均；首点则相当于与自身平均。

夹爪拟合速度、加速度返回为零，不用它们约束夹爪运动。

**不要混淆三个“4”：**

- `filter_window_size: 4`：均值窗口半径，实际 9 点。
- `fitting_deg: 4`：不表示夹爪走四阶多项式拟合；夹爪走上述专用分支。
- 最终四次方映射：机器人执行层的另一项独立操作。

## 7. 第六步：根据延迟选择执行起始索引

代码计算：

```python
time_offset = start_inter_traj_marker - observe_marker
```

这是从动作所用观测时刻到开始块间处理时刻的时间差，并非仅模型前向计算耗时。随后寻找拟合时间轴中第一个满足下式的位置：

```python
timestamp > time_offset
```

若已过去约 370 ms，通常从拟合轨迹的 370 ms 附近开始，而不是第 0 点。此前日志中的正常补偿约为 0.36～0.39 秒，相当于原始第 11～12 帧附近。

当前实现的例外：

- 首次发布拟合轨迹时，若执行索引尚未初始化，索引被设为 0。
- 从其他模式切回控制模式时，读取函数可能把索引重置为 0。
- 若延迟超过全部拟合时间点，搜索不命中，函数返回默认的 0。这是已发现的过期 chunk 回零风险，不代表已证明它导致本批日志中的误释放。

源码：`client/core/realtime_data_manager.py`，`get_start_chunk_index()`，约第 321 行；发布轨迹及索引初始化见 `update_action_chunk_fitted()`。

## 8. 第七步：块间处理不会平滑夹爪的新旧目标

当前配置 `inter_chunk_mode: min_jerk`，但运行中的手臂过渡只作用于手臂关节索引。夹爪维度不通过该分支与旧目标做连续衔接。

因此可能出现：

```text
旧 chunk 当前目标：1.0
新 chunk 对应时刻：0.0
换块后目标：直接使用新 chunk 的 0.0
```

块内滤波不能避免两个 chunk 对相同实际时间给出相反预测。

当前此处没有夹爪多块投票、反向确认、持物状态锁定或 RTC 生成约束。不能因为手臂配置了 min_jerk，就认为夹爪也具备跨块平滑。

源码：`client/core/inter_chunk_fuser.py`，`_min_jerk_chunk_transition_numpy()`，约第 478 行；调用及维度选择见 `client/core/vla_client.py`，约第 834～872 行。

## 9. 第八步：夹爪提前取 5 个拟合采样点

当前配置 `gripper_offset: 5`。在发布新轨迹之前，对夹爪维度做：

```python
shifted[k] = original[k + 5]
```

这里是 5 个拟合采样点，时间为：

```text
5 × 3.75 ms = 18.75 ms
```

不是 5 个原始动作帧，也不是约 167 ms。它让当前使用稍后的夹爪目标，闭合和打开都可能提前。

正向偏移只覆盖前 `N-5` 个点，最后 5 点保留原值，并非统一填充最后一个值。因此尾部不完全等价于整条轨迹刚性前移。偏移绝对值大于等于轨迹长度时，函数直接返回副本、不执行偏移。

源码：`client/core/realtime_data_manager.py`，`_apply_gripper_offset()`，约第 266 行。

## 10. 第九步：索引逐点推进，夹爪每 9 次执行调用下发一次

控制读取先推进索引，再取目标：

```python
index = min(index + 1, last_index)
action = fitted[:, index]
```

因此首次实际读取通常比设置的起始索引再前进一步。末尾索引饱和，后续读取保持最后一个目标。

执行层的 `gripper_freq: 9` 表示每 9 次执行调用发送一次夹爪命令，名义发送间隔：

```text
9 × 3.75 ms = 33.75 ms，约 29.6 Hz
```

实际间隔受调度影响。这里直接发送当次读取的目标，不把 9 个控制目标求平均，因此一部分拟合点不会真正下发。

源码：`client/core/realtime_data_manager.py`，`get_action_fitted()`，约第 350 行；`client/robots/agibot_g1/body_robot.py`，约第 120 行。

## 11. 第十步：裁剪到 [0,1]，再做四次方映射

轮到发送夹爪命令时：

```python
x = float(np.clip(action[15], 0.0, 1.0))
q = x**4 / (x**4 + (1-x)**4)
```

| 映射前 x | SDK 目标 q |
|---:|---:|
| 0 | 0 |
| 0.3 | 0.033 |
| 0.4 | 0.165 |
| 0.5 | 0.500 |
| 0.6 | 0.835 |
| 0.7 | 0.967 |
| 0.8 | 0.996 |
| 1 | 1 |

该函数在 [0,1] 上连续、单调：端点附近压缩波动，0.5 附近放大变化；严格的 0 和 1 不变。它不读取上一条指令、不判断是否持物，也没有滞回记忆。

此前分析中的 `q≤0.2` 视为打开、`q≥0.8` 视为闭合，是统计阈值，不是实际控制程序的二值开关阈值。

源码：`client/robots/agibot_g1/body_robot.py`，约第 129 行。

## 12. 第十一步：左右夹爪组包与 SDK 发布

最终调用：

```python
robot.move_gripper([left_hold, right_q])
```

右夹爪使用上述处理后的目标。

**左夹爪不会执行模型返回的左夹爪轨迹。**当前实现启动时读取左夹爪反馈，计算：

```python
left_hold = clip(left_feedback / 120.0, 0, 1)
```

后续持续发送这个保持值，不应用右夹爪的四次方函数。

SDK `move_gripper()` 对大于 1 的输入存在 `(value-35)/(120-35)` 换算分支。但当前策略命令已经在 [0,1] 内，不触发该分支；SDK 将左右位置值分别装入消息并发布。

这里输出的是位置命令，不是抓持力。实际机械位置、运动速度、接触力和物体是否滑落，还取决于底层执行器及接触条件。不能用本报告直接推断底层驱动内部是否还有控制或滤波。

源码：`client/robots/agibot_g1/body_robot.py`，约第 91、120、140 行；`g1-open-rail/.venv/lib/python3.10/site-packages/a2d_sdk/robot.py`，`move_gripper()`，约第 710 行。

## 13. 对夹爪反复开合的含义

如果参与计算的原始目标持续为 1，均值、吸附、相邻平均、偏移、裁剪和四次方都能保持 1。正常持续闭合序列不会仅因为这套数值操作就自动变成打开。

但下列情况仍然会改变执行目标：

- 新 chunk 对执行时刻的预测从闭合变成打开，换块后直接生效。
- 当前 chunk 内执行位置附近的一段原始预测已经下降，滤波后仍然偏低。
- 未来释放目标进入均值窗口，以及正向偏移，使低值影响提前。
- 延迟或模式切换导致选择了不合适的动作索引。
- 目标在 0.5 附近变化时，四次方增大数值差异。

当前处理链没有“已抓取成功，所以直到允许释放前必须保持闭合”的机制。区分目标数值处理、时间索引和任务阶段判断，是定位误释放的关键。
